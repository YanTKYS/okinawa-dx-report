# 調査方法（methodology）

**確定日：2026年9月15日**
本文書の評価基準は、個別自治体の採点に着手する前に確定させたものである。
採点結果に合わせて基準を変更してはならない。変更する場合は変更履歴を末尾に追記し、
全市を新基準で再採点すること（一部の市だけ再採点してはならない）。

---

## 1. 調査目的と仮説

### 検証仮説（H1）
DXを専門的に推進する組織（DX推進部署・業務改善部署等）の人的体制が充実している自治体ほど、
DX推進が進んでいる。

### 対立仮説
- H0：DX人的体制とDX推進度の間に関係はない
- H2：負の関係がある（例：DXが進んだ結果として担当人員を縮小できる、
  あるいは人員が多い団体ほどレガシー業務の運用負荷が高く新規施策に手が回らない）

**本調査はH1・H0・H2を等しく検証対象とする。**
「人員を増やすべき」という結論に合わせたデータ選択・基準調整は行わない。

### 本調査が目的としないこと
- 自治体間の優劣ランキングの作成
- 特定自治体の評価・格付け

スコアは**相関分析のための説明変数／被説明変数**としてのみ用いる。

## 2. 調査対象

沖縄県内の全「市」11団体。

那覇市、宜野湾市、石垣市、浦添市、名護市、糸満市、沖縄市、豊見城市、うるま市、宮古島市、南城市

- 町村（11町19村）は対象外。市町村合計41団体のうち市は11団体。
- 調査時点（2026年9月15日）において、市への昇格・市町村合併の予定は確認されていない。
  最後の市制施行は南城市（2006年1月1日、4町村合併）である。
  ※この点は沖縄県公式サイトの市町村一覧で最終確認を要する（確度C・未検証）。

## 3. 調査手順

1. 調査設計・仮説定義
2. **評価基準の確定（凍結）** ← 本文書
3. 情報収集（一次資料の取得）
4. データ整理（`data/evidence.csv` への記録、確度付与）
5. 分析（記述統計 → 相関分析 → 外れ値分析 → 交絡要因検討）
6. レポート作成
7. 出典・データ整合性確認

手順2を手順3より前に置くことが本調査の要である。

---

## 4. 情報源の優先順位

以下の順に優先する。下位の情報源は、上位の情報源が存在しない場合の補完としてのみ用いる。

| 優先 | 情報源 |
|---:|---|
| 1 | 自治体公式サイト |
| 2 | 自治体DX推進計画・情報化計画 |
| 3 | 組織機構図 |
| 4 | 職員配置表・行政機構資料・給与定員管理等の公表資料 |
| 5 | 当初予算・主要事業説明資料 |
| 6 | 議会会議録 |
| 7 | 自治体公式プレスリリース |
| 8 | 総務省・デジタル庁・沖縄県等の公的資料 |
| 9 | 報道記事等 |

### 検索結果の取扱い（重要）
検索エンジンの結果一覧・スニペット・検索結果の自動要約は**根拠として採用しない**。
これらは「原資料の所在を特定する手段」としてのみ用い、値の確定は必ず原資料の確認による。

本調査では実際に、検索結果の自動要約が「令和7年度」を "fiscal year 2026" と
誤変換する事例（正しくは2025年度）が発生している。要約を根拠にしない原則の実効性を示す実例として記録する。

## 5. 情報確度の区分

すべてのデータに以下の確度を付与する。

| 確度 | 定義 |
|---|---|
| **A** | 一次資料を直接確認した。原資料のURL・該当箇所を特定できる |
| **B** | 複数の独立した情報から高い確度で確認した。一次資料そのものは未確認 |
| **C** | 間接的情報のみ（検索結果スニペット、第三者サイト、要約等） |
| **不明** | 判断できない |

**分析ではA・Bのデータのみを用いる。** C以下のデータは参考情報として本文に記載するが、
スコア算出・相関分析には投入しない。

---

## 6. 「確認できない」の取扱い（最重要ルール）

**「情報が見つからない」ことと「取り組んでいない」ことを区別する。**

- 情報が確認できない項目は `未確認` フラグを立て、素点は0点とする
- ただし本文・表において「実施していない」とは記載しない
- 各市について `未確認項目数` と `未確認配点合計` を必ず併記する
- 未確認配点が全配点の30%を超える市は、スコアを**参考値**として扱い、
  相関分析の主分析から除外する（感度分析には含める）

### 正規化スコアの併用
未確認項目の多寡による見かけ上の不利を補正するため、以下の2つを併記する。

- **素点（raw score）** ＝ 確認できた得点の合計（0〜100）
- **補正スコア（adjusted score）** ＝ 素点 ÷ 判定可能だった配点合計 × 100

相関分析は**素点・補正スコアの両方**で実施し、結論が両者で一致するか確認する。

## 7. DX推進体制（説明変数）の定義

### 7.1 組織項目（記述用・スコア化しない）

- DX推進担当部署名
- 情報政策担当部署名
- 行政改革・業務改善担当部署名
- DX専任組織の有無
- 組織階層（部／課／室／係／プロジェクトチーム）
- CIO・CDO・CIO補佐官・DXアドバイザー等の有無
- DX専門部署の設置年月（設置からの経過年数）

### 7.2 人員項目（相関分析の説明変数）

人員は**機能別に区分して計上する**。「情報政策課10人」を「DX担当10人」と扱ってはならない。

| 区分 | 内容 |
|---|---|
| ① DX・業務改革 | DX企画、BPR、業務改善、デジタル施策の企画立案 |
| ② 情報システム運用・インフラ | 基幹系・情報系システムの運用保守、ネットワーク、標準化・共通化対応 |
| ③ 情報セキュリティ | セキュリティポリシー、監査、インシデント対応 |
| ④ その他 | 統計、庶務、その他 |

- **区分できない場合は推測せず「確認不能」とする。**
- 兼務者は実人数と兼務の別を記録する（常勤換算は行わない。按分は推測を伴うため）。
- 会計年度任用職員・外部人材（CIO補佐官、DXアドバイザー、委託常駐等）は別カウントとする。

### 7.3 主要説明変数

| 変数 | 定義 |
|---|---|
| `dx_staff` | DX担当職員の絶対数（区分①、兼務含む実人数） |
| `dx_dedicated_staff` | うち専任者数 |
| `dx_staff_per_10000_population` | `dx_staff` ÷ 人口 × 10,000 |
| `dx_staff_per_100_staff` | `dx_staff` ÷ 自治体職員総数 × 100 |
| `external_dx_staff` | 外部デジタル人材数 |

人口・職員総数は出典・基準日を必ず記録する。
人口は住民基本台帳人口または沖縄県推計人口のいずれかに統一し、混在させない。
職員総数は普通会計職員数（総務省定員管理調査ベース）に統一する。

- 「最新技術を導入しているか」ではなく「定着・全庁展開しているか」を見る

## 9. 相関分析の手順【事前登録】

### 9.1 主分析

以下の3組について相関を算出する。

| # | 説明変数 | 被説明変数 |
|---|---|---|
| 1 | `dx_staff`（絶対数） | DX推進度スコア |
| 2 | `dx_staff_per_10000_population` | DX推進度スコア |
| 3 | `dx_staff_per_100_staff` | DX推進度スコア |

> **被説明変数は §13.5 により2層に分離した（2026-09-17）。**
> 主分析は**実装成果スコア**（60点）。総合100点スコアは説明変数と構成概念が重複する項目を
> 含むため、**総合DXスコア**として感度分析に限定する。

### 9.2 統計量
- **Spearman順位相関係数（ρ）を主指標とする。**
  n=11と小標本であり、正規性を仮定できず、外れ値の影響を受けにくいため。
- Pearson相関係数（r）も併記し、両者の乖離を確認する（乖離は外れ値の存在を示唆する）。
- **95%信頼区間を併記する。**

#### 信頼区間の算出方法（2026-09-17 実装）
Fisher z 変換により算出する。

| 係数 | 標準誤差 | 備考 |
|---|---|---|
| Pearson r | `SE = 1/√(n−3)` | 標準的な Fisher z |
| Spearman ρ | `SE = √(1.06/(n−3))` | Bonett–Wright 法 |

区間は `tanh(atanh(coef) ± 1.96·SE)`。**n ≤ 3 では算出しない。**
`data/analysis_results.csv` の `pearson_ci_low` / `pearson_ci_high` /
`spearman_ci_low` / `spearman_ci_high` 列に保存し、画面にも常時併記する。

**区間が0をまたぐ場合、関係の符号すら確定していない。** 小標本では区間が極端に広くなるため、
点推定値だけを引用してはならない。

### 9.2.1 分析の位置づけ（n による呼称の区別）

| n | 呼称 | 扱い |
|---|---|---|
| n < 3 | 算出不能 | 係数を算出しない。「相関なし」ではない |
| 3 ≤ n < 6 | **探索的** | 係数は算出するが**主分析とは呼ばない**。断定的に解釈しない |
| **n ≥ 6** | 主分析 | §9.1 が望ましいとした水準。それでも検出力は低い |

§9.1 は当初から **n≥6** を望ましい水準としていた。n が3〜5の状態を「主分析」と称すると
標本規模の弱さが読み手に伝わらないため、画面・レポート・`data/analysis_results.csv` の
`tier` 列のいずれでも「探索的」と明示する。

### 9.3 有意性の判断と検出力の限界
- n=11におけるSpearman ρ の有意水準5%（両側）の臨界値は概ね **ρ ≈ 0.62**
- すなわち **|ρ| < 0.62 は統計的に有意でない**
- n=11では中程度の相関（ρ≒0.4）を検出する検出力は概ね0.3未満であり、
  **「有意でない＝関係がない」とは結論できない**
- 逆に有意であっても、**因果関係の証明にはならない**

### 9.4 やってはならないこと
- 相関係数から「人員を増やせばDXが進む」と因果を断定すること
- 有意でない相関を「傾向が見られる」と実質的に有意であるかのように記述すること
- 外れ値を理由なく除外して相関係数を改善すること
  （除外する場合は除外前後の双方を必ず併記する）

### 9.5 外れ値分析（必須）
相関係数の算出とは独立に、以下を個別に検討する。
- 少人数でDX推進度が高い市 → 何が代替しているか（外部委託・首長方針・広域連携・外部人材）
- 人員が多くDX推進度が低い市 → 人員が何に充てられているか（①〜④区分の内訳を再確認）

### 9.6 ペア比較（必須）
統計分析に加え、**人口規模が近い2市の対比**を行う。
相関係数よりも実務的示唆が得られる可能性が高いため、本調査では必須の分析とする。

想定ペア（人口規模順・確度Cの人口概数に基づく暫定案）：
- 沖縄市 ⇔ うるま市（いずれも12〜14万人規模）
- 浦添市 ⇔ 宜野湾市（いずれも10〜11万人規模）
- 石垣市 ⇔ 宮古島市（いずれも5万人規模・離島）
- 糸満市 ⇔ 豊見城市（いずれも6万人規模・本島南部）

## 10. 交絡要因の検討【必須】

相関の解釈にあたり、以下を必ず検討する。

| # | 交絡要因 | 確認方法 |
|---|---|---|
| 1 | 人口規模 | 人口を制御変数とした偏相関、または人口階層別の比較 |
| 2 | 自治体職員総数 | 職員100人あたり指標での再検証 |
| 3 | 財政規模 | 標準財政規模・財政力指数・歳出総額 |
| 4 | 情報政策部署がインフラ運用も担当しているか | 機能区分①②の内訳。②の比率が高いほど①に充てられる実質人員は少ない |
| 5 | 外部委託の程度 | 情報システム関係の委託料（当初予算）。委託が厚いほど内部人員は少なくても推進しうる |
| 6 | 外部デジタル人材 | CIO補佐官等の任用の有無（特別交付税措置の対象） |
| 7 | 首長・経営層のDX方針 | 施政方針演説、公約、デジタルファースト宣言等 |
| 8 | DX専門部署設置からの経過年数 | 設置年月からの経過年数。施策の蓄積は時間の関数でもある |
| 9 | 離島・地理的条件 | 石垣市・宮古島市は本島市部と条件が異なる |
| 10 | 広域連携・県の支援事業 | 沖縄県のDX人材確保育成市町村支援事業等の活用状況 |

**「DX人員」と「DX推進度」だけで説明できない事例を特に重視する。**

## 11. 再現性

- すべての数値は `data/evidence.csv` により根拠資料まで追跡可能とする
- 評価基準は `data/scoring_rubric.csv` に機械可読形式で保持する
- 分析を再実行する場合も、本文書の基準を変更してはならない

## 12. 【追記】総務省共通指標 `dx_info_staff`（2026-09-16 追加）

> 本章は §7（DX推進体制の定義）への**追加**である。初版（2026-09-15 凍結）の
> §7.2 `dx_staff` の定義、および §8 の評価ルーブリックは一切変更していない。

### 12.0 追加の理由
§7.2 が定義する `dx_staff`（DX・業務改革の担当職員数）は、自治体が公表する組織図に
係別人数が記載されている場合にしか確定できない。実際に確定できたのは11市中2市
（那覇市・宜野湾市）にとどまり、**11市横断の相関分析に必要な標本数を満たせなかった。**

一方、総務省「令和6年度 自治体DX・情報化推進概要」の個別資料は、
**同一定義・同一基準日（2024年4月1日）・同一調査**で全国市区町村を収録しており、
沖縄県内11市すべてが対象に含まれる。これを共通の説明変数として追加する。

### 12.1 定義

| 変数 | 定義 |
|---|---|
| `dx_info_staff` | 総務省「自治体DX・情報化推進概要」における**DX推進担当課室・情報政策担当課室の職員数（合計）** |

- 基準日：**2024年4月1日**
- 出典：`【R06個別資料】（１）自治体DXの推進体制等（市区町村）.xlsx` シート `1_組織体制（８）`
- **これは広義の指標である。** 情報政策担当課室を含むため、DX専任人数ではない。
- 派生指標：`dx_info_staff_per_10000_population`、`dx_info_staff_per_100_staff`

### 12.2 既存定義との関係（重要）

- **`dx_staff` の定義は変更していない。** §7.2 のとおり、DX企画・BPR・業務改善・
  デジタル施策企画等を担う職員数であり、情報システム運用・インフラ職員とは分離する。
- **総務省の人数を `dx_staff` に入力してはならない。** 両者は別列で管理する。
- UI・レポートでは `dx_info_staff` を「DX・情報関係業務担当職員数」と表示し、
  「DX担当人数」とは表示しない。
- 按分は禁止する。`dx_info_staff` をDX専任・BPR・情報システム運用へ分解してはならない。

### 12.3 二層構造の分析

| 層 | 変数 | 位置づけ |
|---|---|---|
| **主分析** | `dx_info_staff`（広義・総務省・11市共通） | 同一定義で横断比較できるため、相関分析の主指標とする |
| **補助分析** | `dx_staff` / `bpr_staff` / `infra_staff`（狭義・自治体資料） | n が小さいため相関分析には用いず、事例比較・組織類型分析に用いる |

### 12.4 年度差の明示（ラグ分析）

`dx_info_staff` の基準日は2024年4月1日、DX推進度の評価時点は2026年9月15日である。
したがって本分析は **「2024年度時点の人員体制」と「約2年後の2026年時点のDX推進状況」の関係**
を見るラグ分析であり、同時点比較ではない。

逆因果（DXが進んだから人員を増やした）の影響を**多少**避けられる可能性はあるが、
**因果関係を証明するものではない。** 組織改編により2024年度の集計単位が
2026年度の現行課と一致しない可能性も残る。

### 12.5 分離不能な統合部署の扱い

浦添市の行政改革推進課のように、DXとBPRが一体の組織は `dx_bpr_combined_staff`
（統合部署の総数）として記録し、**DX実人数・BPR実人数へ機械的に振り分けない。**

## 13. 【追記】採点の正式化手順（2026-09-16 第5回DR統合時に追加）

### 13.1 唯一の正は凍結ルーブリック

採点の判定基準は `data/scoring_rubric.csv` のみである。
Deep Research 本文に記載された `points` / `得点候補` は**参考外**とし、一切採用しない。
第5回Deep Researchには配点超過の候補が複数あった
（`I-3`=6／満点5、`III-2`=6／満点5、`II-3`=6／満点5、`VI-1`=5／満点4、`I-4`=4／満点条件を満たすのに過小）。

**この誤りを理由にルーブリックを変更してはならない。** ルーブリックを正とし、得点側を修正する。
`tools/build_analysis.py` は `points > max_points` を検出した時点でビルドを停止し、
`tools/test_checks.py` は該当が1件でもあればテスト失敗とする。

Deep Research から採用してよいのは次に限る：事実／証拠／URL／原資料の記載内容／confidence／年度・時点／
「導入済み」「未導入」「運用中」等の状態。

### 13.2 正式化の順序

Deep Research の圧縮CSV（`updates` 列の `item_id:points:source_id` 形式）は移植補助用の表現であり、
そのまま正式CSVへ取り込まない。必ず次の順で正式化する。

> **原資料 → `data/evidence.csv` → `data/scoring_rubric.csv` の条件 → `data/scoring_results.csv`**

採点ファクト表は `tools/scoring_facts.py` に単一の実体として置き、
`build_analysis.py`（採点）と `merge_evidence.py`（根拠統合）の双方がこれを参照する。

### 13.3 status の語彙（4種類に固定）

| status | 意味 | 得点 | 未確認配点 |
|---|---|---|---|
| `満点` | ルーブリックの満点条件に合致 | max | 算入しない |
| `部分点` | 半点等の条件に合致 | 0 < pts < max | 算入しない |
| `0点（確認済み）` | 公的資料に未導入・機能なし・未実施・予定なしが明示 | 0 | **算入しない** |
| `未確認` | 情報を確認できなかった | 0 | **算入する** |

### 13.4 確認済み0点を認める条件（2026-09-17 改訂・旧R3の廃止）

**確認済み0点にできるのは、Deep Research が当該自治体を名指しで「無い／未実施」と
報告している項目に限る**（＝原資料の自治体別セルを読んだ記述があるもの）。

#### 廃止した導出規則R3

初版では「総務省の横断調査は11市すべてを収録しているので、『取組あり』の自治体が
Deep Research で完全に列挙されていれば、列挙されなかった市は非選択＝確認済み0点」
という**補集合からの推定**を用いていた。これを廃止する。

理由：第5回Deep Research はファイル末尾で途切れており、11市中9市分の項目別根拠が
届いていない。**列挙が網羅的である保証が無い状態で否定側を確定するのは危険**であり、
未確認配点を不当に小さく見せ、主分析の対象市を過大に判定してしまう。

該当した28レコード（`II-3`×7・`II-4`×9・`V-2`×6・`V-3`×6）は**未確認へ差し戻した**。
原Excelで非選択を直接確認できた時点で0点へ戻す。

#### 現在残っている確認済み0点（名指し報告のある5件のみ）

| 項目 | 自治体 | 根拠 |
|---|---|---|
| `III-1` | 石垣市・糸満市 | 3システムとも電子決裁機能なし（第4回DRの自治体別表） |
| `I-2` | 名護市 | 計画期間が2025年度で終了し改定未確認 |
| `V-1` | 糸満市 | 2024年度調査で職員育成を未実施と明示 |
| `V-3` | 那覇市 | 第5回DRがデジタル職種・採用区分なしと自治体別に報告 |

Deep Research が件数のみを示し自治体名を列挙していない項目
（`VI-2`「9市でコンビニ交付等を確認」）も、どの市が該当するか特定できないため
**未確認のまま**とする。**件数から市を推測してはならない。**

### 13.5 被説明変数の2層化（2026-09-17 追加）

#### 問題

凍結ルーブリック100点には、説明変数（人的・組織体制）そのものに近い項目が含まれる。

| 項目 | 配点 | 内容 |
|---|---:|---|
| `I-3` | 5 | 全庁的推進本部の設置 |
| `IV-1` | 5 | BPR・業務改善の専管組織／推進体制 |
| `V-1` | 5 | 育成方針・研修体系 |
| `V-2` | 5 | 外部専門人材の活用 |
| `V-3` | 5 | デジタル人材の採用・配置 |

これらを人員数と相関させると、**採点設計に由来する相関が構造的に生じうる**
（体制が厚い自治体は体制項目で得点しやすい）。
得られた相関について「その相関は採点設計が作ったものではないか」という疑義が残る。

#### 対応（ルーブリックは変更しない）

**ルーブリックは凍結のまま変更しない。** 同一の判定結果から部分尺度を集計し、
主分析の被説明変数を実装成果だけで構成する。

| 尺度 | 構成 | 満点 | 用途 |
|---|---|---:|---|
| **実装成果スコア** | II 行政手続DX ＋ III 内部業務DX ＋ `IV-2` BPR実施実績の公表 ＋ VI 住民サービス・データ活用 | **60点** | **主分析の被説明変数** |
| **総合DXスコア** | 21項目すべて | 100点 | **感度分析のみ** |

`IV-1`（専管組織の有無）は体制側なので実装成果スコアから除外し、
`IV-2`（実績の公表）のみを含める。

正規化・未確認率・30%除外ルールは総合スコアと**同一手順**で実装成果スコアにも適用する
（`impl_score` / `impl_score_adjusted` / `impl_unconfirmed_rate` /
`impl_main_analysis_eligible`）。主分析の除外判定は**実装成果スコアの未確認率**で行う。

各項目がどちらの尺度に属するかは `data/scoring_results.csv` の `scale` 列
（`実装成果` / `体制`）で確認できる。
